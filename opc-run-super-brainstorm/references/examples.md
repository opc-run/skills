# 使用示例（超级智囊团）

主文件 [SKILL.md](../SKILL.md) 只给判断规则，具体话术演示在这里。需要时按需读，不要一次性全量灌进上下文。

---

## 示例 1：拿主意（最常用）

**用户**："我一个人做跨境电商，月流水 3 万，该不该招人？"

**你的处理**：

1. `python3 scripts/bootstrap.py`（首次输出能力清单与 Key 引导）

2. 把用户的话补完整（身份 + 现状 + 决策点），确认关键数字来自用户本人后：

   ```
   python3 scripts/brainstorm.py ask "我是一个人做跨境电商的卖家，月流水 3 万，客服和打包占了我一半时间，该不该现在招第一个全职？"
   ```

3. 脚本会**一位导师说完就给你看**：每出现一位导师的新发言就先转述给用户，不要憋到最后

4. 讨论结束（没有决议），**保留结尾的引导行与来源行**，最后给一句你的归纳 ——
   只点出分歧在哪，不要自己下结论（结论是站内完整版的事）

5. **导师向你提问时，脚本已经标出来了**（发言下面的 `> ❓ **某某 在等你回答**`，
   对应 `--json` 里的 `wait_for_user: true`）—— 你的活是**把欠账点清楚**：

   例：德鲁克说「你问错了问题，这不是招不招人，是杠杆。你说的月流水 3 万，是净利润还是 GMV？」
   → 该条带 `wait_for_user`，你**照它的标记说**「德鲁克在等你回答」，并告诉用户站内能答。

   ⚠️ **不要自己从内容里判断有没有提问**（提问标记已排除修辞性反问，
   已排除"这难道不矛盾吗——不是，因为…"这类修辞反问；你猜会误判）。

   然后**按身份给动作**（判据：结尾引导行里有「打开这场讨论」= 已有账号）：

   - **有账号**：「[打开这场讨论](web_url)」+ 点出「导师问你的那 N 个问题已经跟着这场讨论进了你的智囊团」
   - **匿名**：「[登录后接着聊这场讨论](claim_url) —— 登录完会自动回到这场，导师问你的那 N 个问题也在里面」
     —— 链接**原样给用户**，不要说成"先注册再回来找"，那会让人以为要重头再来
   - **匿名 · 已认领**（脚本说"已经存到你的账号里了"）：别再给链接，改说「去站内工作台就能看到它」
  - **确认被别人认领**（脚本说"已被另一个账号认领"）：⚠️ **别说成"你的"**，改说
    「这场讨论被另一个账号认领了，可能链接被转发过；去站内登录你自己的账号，在工作台里找找」

   ★ 引导重点是「去答那 N 个问题」，不是罗列"5 位导师、不限轮次"这类功能差异 ——
     用户此刻真正想做的只有那一件事。⚠️ 也别用"收口""圆桌决议"这类词（用户看不懂，
     说「结论」就行），也别再说"接不上、只能重新开一场"，那是错的话术。

> ★ 每场**保证至少 3 位导师出席**，最多 5 位（LLM 少推荐时会自动补齐并记日志）。
> 人数由议题复杂度决定：议题窄就 3 位，需要多角度交叉时 LLM 会推荐到 5 位。
> 极少数情况下有导师没能发言（AI 响应异常），脚本会用一行平实的文字说明
> 「本场有 N 位导师未能发言，其余发言可正常参考」——
> **照原样转述即可，不要额外渲染成"这场讨论失败/不完整"**。
> 用户已经拿到了可用内容，再加一段告警只会让人怀疑剩下的发言也不可信。

## 示例 2：用户想先看都有谁

**用户**："你们这智囊团都是些什么人？"

**你的处理**：

1. `python3 scripts/brainstorm.py mentors`（只读，不消耗额度）

2. 用表格呈现，挑 2~3 位和用户问题最相关的介绍一下，然后引导他提交议题

---

## 示例 3：结果没说完 / 想再看一遍

**用户**："刚才那个讨论再发我一次"

**你的处理**：

1. 用上一轮 `ask` 输出里的 **「任务 ID」**：`python3 scripts/brainstorm.py task <task_id>`

   ⚠️ **只认「任务 ID」**。同一份输出里那些链接（`/app/session/discuss/<数字>`）里
   另有一串数字，那是**站内会话 ID**，拿去跑 `task` 会得退出码 4。
   两个位数相同、长得极像（位数由服务端发号器决定，15~20 位都可能出现，不要按位数判断），
   但只有「任务 ID」能用来取回结果 —— 详见 SKILL.md
   「输出里会出现两个雪花 ID」那一节

2. **绝不要重新 `ask`** —— 那会真的再扣一次额度

---

## 示例 4：额度用完

**用户**：继续追问，但脚本返回退出码 3

**你的处理**：

1. 原样转述脚本输出的引导

2. `python3 scripts/brainstorm.py quota` 看重置时间

3. **先引导去站内完整版**（`https://opc.run/app/session/list?from=skill`，不受 Skill 额度限制）

4. 老结果用 `task <task_id>` 取回（零消耗），不要凭空编一场讨论

---

## 示例 5：点数不够（只有配了 API Key 才会碰到）

**用户**：已配 Key，提交时被拒，退出码 6

**你的处理**：

1. 原样转述脚本输出 —— 它已经说明了要多少点、这次没扣点也没消耗额度，并给了签到链接

2. **不要**说成"Skill 免费"或"你账号有问题"：这是正常状态，领点即可

3. 用户不愿领点时，引导去站内完整版（不受 Skill 额度与点数限制）
